    \begin{abstract}
        This project conducts a comprehensive performance evaluation comparing database management systems (PostgreSQL and openGauss) against manual file operations (including the JSON and BEVE format) using an employee database schema. This experiments reveal that PostgreSQL is generally faster than openGauss, and using DBMS can lead to less resource usage and provide significant advantages for complex queries and maintainability.
    \end{abstract}
    \tableofcontents
    
    \section{Project Overview}
    The \textbf{database management systems} (DBMS) have become fundamental to modern data management, but understanding their performance characteristics compared to traditional file operations remains crucial. This projects evaluates PostgreSQL and openGauss against file-based data management using a realistic employee database schema. The benchmarks are implemented in C++.

    \subsection{Measurement Methodology}
    
    The timing measurements are all conducted using the \texttt{ADVANCED\_BENCHMARK()} marco of \textbf{Catch2} library. Each experiements is sampled for 10 times and each sample contains at least 1 iteration. Then average and standard deviation is reported.
    
    To ensure noninterference across multiple benchmarks, separate transactions/file loading are used in individual benchmarks.

    \section{Analysis and Discussion}
    \textbf{1. DBMS vs. File Operations}:
    \begin{itemize}
        \item For any applications that need complex data query and modifications, DBMS is way better than manual file operations. They eliminate the need to load the whole file into memory every operation, and reduce the develop burden as we no longer need to write ad-hoc code for specific tasks. They can also optimize our operations and maintain data integrity through transactions.
        \item For very specific circumstances where we only need to perform very simple tasks on already cached data, e.g. traversal, the file-based approach can be faster. This is mainly because it performs a direct linear scan without overhead of SQL parsing, optimizing, planning, and client-server communication. But these scenarios are considerably rare in real-world applications. We can already see from the results that the BEVE format can provide performance close to DBMSs.
    \end{itemize}    
    \textbf{2. PostgreSQL vs. openGauss}:    
    
    Across almost every test, PostgreSQL demonstrated significantly better performance than openGauss. The performance gap was most pronounced in complex queries (Retrieval Test 2, 3) and large-scale updates (Update Test 2), where PostgreSQL was often twice as fast or more. We consider that this lead can be attributed to several factors: more mature optimizer, efficient execution engine, less overhead on personal computer (since openGauss is designed specifically for enterprises).
    
    \section{Conclusion}
    
    This project conducted a performance evaluation of two DBMSs, PostgreSQL and openGauss, against manual file operations using JSON and BEVE formats for an realistic employee database. The results lead to two conclusions:
    \begin{itemize}
        \item First, DBMS are superior to file-based operations for dynamic applications involving complex queries and data modifications. Although the manual file processing is faster if we have the whole file in memory, the extreme cost of fil I/O renders this approach impractical since it will require much more memory and is inefficient for data updates (since our naive implementation don't have indexing and needs an linear search when finding the data).
        \item Second, in a direct comparison of the two DBMSs, PostgreSQL exhibited consistently better performance then openGauss across a wide range of benchmarks.
    \end{itemize}
    
    In summary, while optimized file formats like BEVE have a potential usage in high-performance scenarios, the use of DBMS is recommended for nearly all applications due to its performance, scalability, and maintainability.
